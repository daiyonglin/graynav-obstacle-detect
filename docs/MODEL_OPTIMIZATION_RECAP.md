# GrayNav 模型优化路线复盘

## 1. 背景与目标

项目使用 `SC132GS 720x1280@90fps Mono` 单通道灰度传感器，目标是在 A1 开发板上实现稳定、精准、快速的盲人避障目标检测。A1 板端资源受限：

- CPU：单核 ARM Cortex-A7，最高 1.2GHz
- NPU：0.8TOPS@INT8
- 内存：DDR3L 16bit 1Gb
- 存储：256Mb Nor Flash
- 模型部署：需要经过模型切分、ONNX/专用格式转换、`.m1model` 上板
- 后处理：YOLO DFL、NMS、坐标还原等复杂逻辑放在 CPU 端实现

最初现象是：PC 端直接使用官方 `yolov8n.pt`，将灰度图复制成三通道输入，检测效果较好；但模型切分并转换上板后，出现检测框不稳定、漏检、错检、漂移等问题。

因此模型优化工作围绕两个问题展开：

1. 单通道灰度图如何更好适配 RGB 图像上预训练的 YOLOv8n。
2. PC 端模型输出与板端 head6/C++ 后处理链路如何保持一致。

本文只复盘模型优化路线与实验结果，板端后处理一致性另行推进。

## 2. 原始基线：灰度复制三通道输入 YOLOv8n

最基础方案如下：

```text
单通道灰度图 Y
-> 复制为 [Y, Y, Y]
-> 输入官方 yolov8n
```

这个方案的优点是部署链路最简单，仍然保持标准 YOLOv8n 三通道输入和 head6 输出，不需要改动模型结构或板端预处理。

PC 端测试表明，官方 `yolov8n.pt` 对灰度复制三通道输入具有较强鲁棒性，能够正常检测常见目标。这个现象说明，YOLOv8n 的早期卷积虽然在 RGB 数据上训练，但并非完全依赖颜色信息，亮度、边缘、纹理和形状仍然能支撑大部分检测能力。

但是这个方案存在两个问题：

- 没有专门针对 SC132GS 灰度图像域微调。
- 从比赛创新性角度看，直接使用官方预训练模型说服力不足。

因此后续尝试了多种灰度适配方案。

## 3. LUT GrayChannelAdapter

### 3.1 设计思路

LUT 方案希望用可学习查表方式，将单通道灰度值映射成三个伪 RGB 通道：

```text
Y -> LUT_R[Y], LUT_G[Y], LUT_B[Y] -> YOLOv8n
```

每个 LUT 可以看作一个长度为 256 的可学习映射表。训练完成后，LUT 可以固化为 3 组 256-entry 查表参数，部署时 CPU 开销极低。

### 3.2 实验结论

LUT 方案没有带来明显提升。主要原因是：

- 它只能做逐像素强度映射，不能感知局部纹理、边缘或目标结构。
- 对于目标检测任务，物体边界、形状、局部上下文比单个像素灰度值更重要。
- LUT 生成的三个通道之间表达能力有限，很难弥补灰度图缺失颜色后的 domain gap。

结论：LUT 适合做轻量亮度校正，但不足以作为主要模型优化路线。

## 4. Conv GrayChannelAdapter

### 4.1 设计思路

Conv Adapter 用轻量卷积模块替代 LUT：

```text
Y -> 轻量卷积 adapter -> 三通道伪 RGB -> YOLOv8n
```

相比 LUT，卷积可以利用局部空间信息，理论上能够学习边缘、纹理和局部对比度。

### 4.2 实验结论

Conv Adapter 仍然没有显著超过灰度复制三通道基线。部分实验中指标下降，并且带来了额外推理开销和部署不确定性。

主要问题是：

- 如果 YOLO 主体冻结，adapter 单独学习能力不足。
- 如果 adapter 放入模型图，A1 工具链算子支持和切分转换风险增加。
- 如果 adapter 放在 CPU 前处理，板端实时性压力增加。

结论：单独训练一个前置 Conv Adapter，不足以稳定提升检测效果。

## 5. G2RGB / BC-GMFE-DCA 前置模块

### 5.1 设计思路

这一阶段尝试更复杂的灰度到三通道表示，包括：

- 多尺度灰度特征
- 边缘和纹理特征
- 局部对比度增强
- 动态通道融合或注意力

核心目标是让前置模块生成比 `[Y,Y,Y]` 更接近 RGB YOLO 预训练分布、同时更适合目标检测的三通道输入。

整体流程如下：

```text
灰度图
-> 结构化灰度特征增强模块
-> 伪三通道
-> YOLOv8n
```

### 5.2 实验结论

这一类复杂 adapter 的结果仍然不理想。典型结果是：

- 全 COCO AP 可能出现极小提升。
- 导航相关子集 AP/AP50/AR100 往往下降。
- 推理前处理耗时明显增加。

BC-GMFE-DCA stage2 30k anchor 的结论是：

- COCO all AP 只有约 `+0.0009` 的微弱提升。
- 导航相关指标下降。
- 不具备继续上板测试的价值。

核心教训是：如果 YOLO 主体基本冻结，复杂前置模块很难单独让 RGB 预训练检测器理解新的灰度结构表示。

## 6. GrayNav-YOLOv8n 灰度域微调 + GMFE 联合训练

### 6.1 重新定义实验对比

前面实验暴露出一个问题：只做前置 adapter，不联合训练 YOLO 主体，收益不足。因此我们设计了更严谨的联合训练实验。

这次不再把 RGB 原图 YOLO 作为主要 baseline，而是统一为：

- 同一单通道灰度来源
- 同一 COCO 真值标签
- 同一 8 类 GrayNav-Obstacle8 类别映射
- 同一 YOLOv8n 初始化权重
- 同一训练流程
- 同一验证集和扰动评估

主要比较两组模型：

```text
M1_ggg_yolov8n_ft:
灰度复制三通道 [Y,Y,Y] + YOLOv8n 微调

M2_gmfe_yolov8n_ft:
灰度图 -> GMFE [B,S,T] 三通道编码 + YOLOv8n 微调
```

### 6.2 类别定义

训练使用 8 类避障语义：

| ID | 类别 |
|---:|---|
| 0 | person |
| 1 | chair/seat |
| 2 | table/desk |
| 3 | sofa/bed |
| 4 | bag/suitcase |
| 5 | small_object |
| 6 | vehicle/bicycle |
| 7 | generic_obstacle |

### 6.3 数据集

数据来自 COCO2017：

- 训练集：从 `train2017.zip` 流式抽样 30000 张，避免全量解压占满 50G 数据盘。
- 验证集：COCO `val2017` 全量 5000 张。
- 标注：官方 `instances_train2017.json` 和 `instances_val2017.json`。
- 输入：所有图像先从 RGB 转成单通道灰度，再生成 M1/M2 所需三通道输入。

这保证了实验不是在 RGB 原图上评估，而是在单通道灰度来源上比较两种方法。

### 6.4 GMFE 编码

GMFE 使用三个结构化通道：

```text
B: 5x5 Gaussian/box blur 后的亮度通道
S: Sobel 能量 dx^2 + dy^2
T: 局部方差 E[Y^2] - E[Y]^2
```

设计时避免使用复杂算子，例如 `sqrt`、`softmax`、逐像素除法等，以便未来板端 CPU 预处理可实现。

### 6.5 训练策略

训练从官方 `yolov8n.pt` 初始化，使用三阶段策略：

1. Warmup：冻结浅层或部分 backbone，让检测头先适应 8 类任务。
2. Adapt：全模型微调，让 backbone 和 head 共同适应灰度域。
3. Stabilize：关闭强增强，降低训练和部署分布差异。

训练过程中使用：

- 4090 GPU
- AMP 混合精度
- TensorBoard
- tqdm 进度显示
- YOLOv8n 384 输入尺寸

### 6.7 结论

GMFE 只在噪声和运动模糊场景下有极小提升，但在 normal、低光、强光、低对比等更重要场景下明显下降。

此外，GMFE 的 Sobel 能量通道和局部方差通道相关性偏高，很多样本达到 `0.7-0.89`，说明这两个结构通道没有提供足够互补的信息。

因此，M2 GMFE 不适合作为当前上板候选。当前最可靠候选是：

```text
M1_ggg_yolov8n_ft:
灰度复制三通道 + YOLOv8n 灰度域微调
```

## 7. 当前总体结论

截至目前，模型优化实验得到以下结论：

1. 官方 YOLOv8n 对灰度复制三通道输入本身具有较强鲁棒性。
2. LUT、Conv、G2RGB、BC-GMFE-DCA 等单独前置 adapter 没有稳定超过灰度复制三通道基线。
3. 固定手工 GMFE 三通道结构在联合训练后仍然不如灰度复制三通道微调。
4. 当前最值得上板验证的是 M1：灰度复制三通道 + 8 类灰度域微调 YOLOv8n。
5. 如果 M1 上板仍然明显不稳定，优先怀疑模型切分、量化、head6 解码和 C++ 后处理一致性，而不是 PC 端模型能力本身。

## 8. 后续建议

下一阶段不建议继续投入固定伪 RGB adapter 路线，而应转向以下方向：

### 8.1 先验证 M1 上板效果

流程：

```text
M1 best.pt
-> head6 ONNX
-> .m1model 转换
-> A1 上板
-> Aurora 实时画面验证
```

重点观察：

- 检测框是否比原始 YOLOv8n 更稳定。
- 低光、强光、运动模糊下是否改善。
- OSD 类别、距离、风险等级是否稳定。

### 8.2 建立 PC/ONNX/板端一致性验证

必须固定 golden cases，对比：

```text
PyTorch YOLO
-> ONNX full
-> ONNX head6 raw output
-> Python head6 decoder
-> C++ board decoder
-> A1 .m1model output
```

关键检查：

- 6 个 head 输出顺序
- 分类通道数
- DFL reg_max
- stride 对应关系
- HWC/CHW layout
- letterbox padding
- reverse letterbox 坐标还原
- NMS 阈值
- INT8 量化校准集

如果 PC 效果好、板端效果差，这条一致性链路优先级最高。

### 8.3 重新设计下一代模型优化路线

新的模型创新应重点考虑：

- YOLOv8n 第一层灰度输入结构改造。
- RGB 第一层权重折叠初始化到单通道。
- 灰度域 backbone 浅层微调。
- 大模型 teacher 到 A1 student 的蒸馏训练。
- 更贴近盲人导航场景的数据集和验证集。
- 在不破坏 A1 算子限制的前提下做轻量结构创新。

后续模型优化不应只追求“灰度变伪 RGB”，而应围绕真实板端稳定性、量化鲁棒性和避障场景指标重新设计。
